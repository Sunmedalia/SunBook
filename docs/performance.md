# 性能优化与验证

2026-10-17，在 Apple M4、macOS arm64、Go 1.26.2 上验证。每项基准运行 5 次，以下采用中位数；这些是特定场景的微基准，不代表完整操作的端到端延迟。

## 实测结果

| 场景 | 优化前 | 优化后 | 变化 |
| --- | --- | --- | --- |
| 十万行插入并撤销 | 2.195 ms；7.51 MB 分配 | 0.026 ms；589 B 分配 | 耗时约降低 98.8% |
| 十万行编辑、读取全文快照并撤销 | 4.377 ms；17.48 MB 分配 | 0.122 ms；3.41 MB 分配 | 耗时约降低 97.2%，分配约降低 80.5% |
| 1000 条诊断下绘制 110×32 界面 | 0.666 ms | 0.214 ms | 耗时约降低 67.9% |
| 终端输出解析并立即绘制 | 0.376 ms | 0.375 ms | 单次绘制成本基本持平；实际事件循环会合并密集输出的绘制 |
| 16 个 256 KiB 文件完整校验 | 1.796 ms；4.33 MB 分配 | 1.589 ms；19.1 KB 分配 | 分配约降低 99.6% |
| 同样 16 个文件，仅检查未变化的元信息 | 原来每轮完整读取 | 0.0177 ms；4.86 KB 分配 | 普通轮询无需读取文件内容 |

原始记录：[优化前](benchmarks/optimization-before.txt)、[优化后](benchmarks/optimization-after.txt)。新增的全文快照基准通过 Go overlay 载入提交 `463ffa9` 的旧缓冲区实现，使用相同测试代码串行比较前后版本。

插入并撤销基准可以复用原始文本，因此收益特别明显。全文快照场景仍需拼接整个已编辑文档；目前没有消除所有 O(N) 操作，行索引更新也仍需调整后续行的偏移。

## 语法高亮与多光标（2026-10-18）

Linux amd64、Go 1.26.2，每项 5 次取中位数，`make bench` 可复现。

| 场景 | 优化前 | 优化后 | 变化 |
| --- | --- | --- | --- |
| 5000 个光标时绘制 110×32 界面 | 10.14 ms | 0.71 ms | 约快 14 倍，与无多光标的绘制持平 |
| 4 KB Go 文件语法高亮 | 10.59 ms | 6.16 ms | 约降低 42%，主要来自缓存按文件名匹配的词法分析器 |
| 120 KB Go 文件语法高亮 | 210 ms | 199 ms | 约降低 5%；剩余时间几乎全部是 chroma 正则分词 |

- 绘制时只检查与可见行相交的选区；400 个随机场景（重叠、反向、跨行、行尾和横向滚动）的逐格字符与样式与优化前完全一致。
- 词法分析器按文件名缓存，样式按 token 类型缓存；仓库内 171 个文件在 6 套主题下的高亮结果与优化前完全一致。
- 编辑后保留上一版本的高亮，按本次编辑平移区间（与选区偏移映射规则相同），直到新快照分词完成；此前每次按键都会清空整个文件的颜色。重新加载等无编辑记录的变化仍丢弃旧高亮。
- 分词仍从文件开头完整进行：chroma 无法从公开状态安全地中途恢复，局部重分词可能产生错误颜色，因此未采用。

## 行为与兼容

- LSP 仍顺序发送消息，使用异步响应等待；每客户端最多 8 个在途请求、1024 条待发送消息。普通请求最多等待 8 秒，写入传输另设 8 秒保护。取消补全不会终止正常写入。请求拥塞时立即失败；文档通知无法入队时关闭客户端并提示重启，避免状态不同步。
- 服务器声明 `textDocumentSync.change = 2` 时按范围增量同步：每次编辑只发送改动的 UTF-16 范围和新文本，撤销/重做同样适用。仅当缓冲区与服务器所见为同一个、且版本恰好加 1 时发送增量，重新加载、跳过的版本等情况回退全文；版本未变不再重复发送。其他服务器继续使用全文同步。
- 同一文档相邻的变更通知可以合并：范围变更按顺序追加，全文变更替换待发内容；请求、保存和关闭事件是合并边界。
- 界面按变化刷新，连续帧间隔至少 16ms；高亮、搜索、补全和提示到期共用定时调度。后台终端继续处理输出，但不会要求绘制隐藏面板。PTY 尺寸在下一次输入前更新，不等待下一帧。
- 磁盘每 2 秒检查大小、时间、身份和权限，有变化即校验；每 30 秒、窗口重新获得焦点时完整校验。保存仍执行完整的冲突检查。保留元信息的外部修改可能要到完整校验时发现。
- 磁盘工作线程验证读取一致性；UI 通过文档版本、缓冲区身份、路径和保存代次排除过期结果，不在回调中重复读取文件。
- 撤销粒度和最多 1000 条历史保持不变。累计新增或删除内容达到 8MiB 后，编辑空闲 1 秒启动后台存储检查；废弃数据超过 8MiB 且超过存储一半时压缩。当前内容、撤销和重做仍引用的数据全部保留；这不是进程内存的固定上限。
- 诊断按文档版本和诊断批次缓存字节范围，最多保留 256 行的惰性显示索引，避免超长诊断扩展成无限行表。
- 配置格式和 CLI 无变化。命令面板显示有效快捷键；Explorer 严格限制 10000 条显示结果，旧扫描会被取消，截断时提示使用 Quick Open。

## 验证与复现

```sh
make check
make smoke
make bench
go test ./internal/text -run '^$' -fuzz FuzzBufferHistory -fuzztime=10s

# 交叉编译测试程序，不执行 Linux 测试：
mkdir -p /tmp/sunbook-linux-tests
GOOS=linux GOARCH=amd64 go test -c -o /tmp/sunbook-linux-tests/ ./...
```

本机通过全量竞态测试、go vet、依赖校验、真实 PTY 冒烟、屏幕解析器单元测试及 Linux amd64 测试程序交叉编译。随机编辑/撤销/重做模糊测试运行 10 秒，约 14 万次执行，无失败。

新增回归覆盖慢 LSP、请求取消、停止读取、队列溢出、通知顺序、回调次数、空闲刷新、定时提示、诊断缓存、保留元信息的外部修改、保存期间的旧校验结果，以及存储压缩后的撤销、重做和并发编辑。

PTY 冒烟测试同时检查原始控制序列和重建后的屏幕文字；差分输出可能省略原来已在正确位置的字符，不能要求所有显示文字都在单次字节输出中连续出现。

Linux 运行时测试由现有 CI 执行，本次本机未执行。环境未安装 gopls、pyright-langserver、typescript-language-server，因此未运行可选的真实语言服务器集成；LSP 调度使用可控的模拟服务器验证。

增量同步（2026-10-18，Linux amd64）：随机编辑/撤销/重做的变更回放与模拟服务器端到端测试覆盖多光标、换行、中文、Emoji 代理对和组合字符；可选的 `TestRealServersIncrementalSync` 在 gopls 与 pyright 上验证 300 步随机编辑后的文档符号与全文打开一致（未安装 typescript-language-server，该项跳过）。在 1 MB / 5 MB 文档中输入一个字符，客户端计算并编码变更的耗时由 4.85 ms / 17.2 ms 降至 0.81 ms / 2.25 ms（中位数），发送内容由整篇文档降至约 100 字节；剩余耗时主要来自编辑后拼接全文快照，界面绘制同样需要它。
